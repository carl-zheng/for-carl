# Concept Brief Output Contract

Use the lightest output that answers the user's request. For a normal multi-concept request, use the following structure.

## Grounding summary

- Known product truth
- Audience evidence
- Offer and approved claims
- Available visual proof
- Material assumptions
- `CLAIM REQUIRED` items
- `PROOF GAP` items
- Source conflicts or attribution limits

## Recommendation

Name the strongest concept first and explain why it has the best combination of purchase motivation, proof, producibility, continuity, and learning value.

## Concept brief

For each selected concept provide these core fields:

1. **Concept name and creative territory**
2. **Audience situation**
3. **Consumer truth, tension, and purchase motivation**
4. **Primary journey role** and optional secondary role
5. **Big idea** in one memorable sentence
6. **Dominant memory**: the one thing the viewer should remember tomorrow
7. **Hook mechanism** and, only if useful, one short illustrative opening line
8. **Product role and narrative spine**: opening -> development -> product -> demonstration -> proof -> offer/action; keep this conceptual, not scene-by-scene
9. **Demonstration and proof strategy**, with evidence labels on material claims
10. **Offer role and proposed duration**, including why the idea has enough substance for that duration
11. **AIP continuation idea**
12. **Landing-page promise**

Add the following only when they help the user decide or test:

- meaningful variant opportunities
- likely failure mode
- cheapest decisive test
- detailed claim/evidence table
- compact downstream handoff with approved facts and unresolved requirements

## Ranking

Provide a concise comparison using the criteria in [creative-framework.md](creative-framework.md). State any fatal flaw separately from the numeric score.

Do not write the final script unless the user separately requests scriptwriting.
